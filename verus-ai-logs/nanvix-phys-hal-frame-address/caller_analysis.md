## Caller Expectations (in-scope functions)

### `FrameAddress` (the newtype) — `struct FrameAddress(PageAligned<PhysicalAddress>)`
- Callers treat it as an **opaque, page-aligned physical frame address**: a
  `Copy` handle they pass by value into MMU/page-table/frame-allocator code.
- Callers assume the wrapped address is always **page-aligned** (the type
  invariant `self@ % spec_page_size() == 0`). Both `from_frame_number` and
  `from_raw_value` go through `PageAligned::from_address`, and `new` takes an
  already-`PageAligned` argument, so callers never have to re-check alignment.
- Callers rely on the View being `int` (the abstract physical address). They
  do **not** care that it wraps `PageAligned<PhysicalAddress>` internally; the
  newtype representation could change without affecting them.
- `mm/phys/frame.rs` specs reason about `frame@` (e.g.
  `!old(self)@.allocated_frames.contains(frame@)`), so the View must equal the
  abstract physical address, and `inv()` (alignment) must be available.

### `from_frame_number(frame_number: FrameNumber) -> Result<Self, Error>`
- Callers assume: on `Ok(fa)`, `fa` is a valid, page-aligned `FrameAddress`
  whose abstract address corresponds to `frame_number` scaled by the page
  size (i.e. `fa@ == frame_number * PAGE_SIZE`, and `fa.inv()` holds).
- Callers assume: on `Err`, no `FrameAddress` is produced; they propagate the
  error with `?` (page tables/dir) or re-log and return it (frame allocator).
  The error path is taken when the frame number is out of representable range.
- Used as the inverse of `into_frame_number`: page-table/dir code reads a PTE/
  PDE frame number and reconstructs the physical frame address.
  `mm/phys/frame.rs::alloc`/`alloc_contiguous` use it to turn an allocator
  bitmap index into a returned `FrameAddress`.
- Would break callers if: it returned a non-page-aligned address, or lost the
  round-trip identity with `into_frame_number`.
- Would NOT break callers: how the `FrameNumber -> address` arithmetic is
  implemented internally, or the concrete `Error` value beyond "is it `Err`".

### `into_frame_number(self) -> FrameNumber`
- Callers assume: returns the frame number identifying this frame, i.e. the
  inverse of `from_frame_number` (`fa@ / PAGE_SIZE`). Total (no `Result`),
  because a `FrameAddress` is always valid/aligned by construction.
- Concrete uses:
  - `mm/phys/frame.rs::free`/`share`/`refcount`:
    `frame.into_frame_number().into_raw_value()` → used as an **index** into
    the refcount/bitmap (`self.refcount.len()` bound check). Callers rely on
    the returned number being the allocator-relevant frame index.
  - `hal/.../mmu/page_directory.rs`, `page_table.rs`: feed the frame number
    into `PageTableEntry::new` / `PageDirectoryEntry::new` when building
    hardware paging structures.
- Would break callers if: the value were not the same index that
  `from_frame_number` consumes (round-trip must hold), or not bounded by the
  number of physical frames.
- Would NOT break callers: internal address-to-number computation.

### `from_raw_value(raw_addr: usize) -> Result<Self, Error>`
- Single genuine caller: `mm/virt/boot_init.rs:207`, building identity-map
  page-table fill entries from a raw virtual/physical address during boot.
- Callers assume: on `Ok(fa)`, `fa@ == raw_addr` (newtype identity) **and**
  `fa.inv()` (page-aligned). On `Err`, the raw value was not a valid /
  not page-aligned physical address; the caller propagates via `?`.
- Would break callers if: `Ok` returned an address differing from `raw_addr`,
  or accepted a misaligned value.
- Would NOT break callers: the internal `PhysicalAddress::from_raw_value` +
  `PageAligned::from_address` chain.

### `into_raw_value(self) -> usize`
- Heaviest-used projection (≈14 genuine sites in `vmem.rs`, `hwpt.rs`,
  `kframe.rs`, `pm/.../mod.rs`). Callers assume: returns the **raw physical
  address** as `usize`, exactly equal to the abstract view
  (`result as int == self@`) — the already-present trusted `#[verus_spec]`.
- Concrete uses depend on exact numeric identity:
  - `vmem.rs`: `frame.into_raw_value() + offset` to compute byte addresses for
    cross-address-space `memcpy`/`memset` and pointer casts (`as *mut u8`).
  - `hwpt.rs`: passed as the physical address into `mmu::map`/`map_in`.
  - `kframe.rs::clear`: `self.base.into_raw_value() as *mut u8` for an
    identity-mapped `memset`.
  - `pm/.../mod.rs`: page-directory physical address loaded into CR3
    (`as u32`).
- Would break callers if: the returned `usize` were not the literal physical
  address (offsets, pointer casts, and CR3 loads would target wrong memory).
- Would NOT break callers: anything about how the value is stored internally,
  as long as the numeric identity to `self@` holds.

## Abstract Resource
`FrameAddress` is an **opaque, page-aligned physical frame address** — a `Copy`
value object (not an owning resource) that names one physical frame. It is the
shared currency between the physical-frame allocator (`mm::phys`), the virtual
memory manager (`mm::virt`), and the hardware MMU/paging layer
(`hal::arch::mmu`). Its two equivalent identities are the **raw physical
address** (`into_raw_value`/`from_raw_value`) and the **frame index**
(`into_frame_number`/`from_frame_number`); callers convert freely between them.

## Key Invariants (caller perspective)
- **Page alignment**: every `FrameAddress` is page-aligned
  (`self@ % spec_page_size() == 0`). Guaranteed at every constructor
  (`new`, `from_frame_number`, `from_raw_value`); callers never re-check it.
- **Raw-value identity**: `into_raw_value(self) as int == self@`, and
  `from_raw_value(r) == Ok(fa) ==> fa@ == r`. Critical: callers do pointer
  arithmetic, pointer casts, and CR3 loads on the raw value.
- **Frame-number round-trip**: `from_frame_number(n).into_frame_number() == n`
  and the number equals `self@ / PAGE_SIZE`. Used as an allocator/bitmap index.
- **View = abstract physical address (`int`)**: specs in `mm::phys::frame`
  reason about `frame@` (set membership in `allocated_frames`/`free_frames`),
  so the View must be the physical address, independent of the inner
  `PageAligned<PhysicalAddress>` representation.
- **Error path is value-free**: failing constructors return `Err` and yield no
  `FrameAddress`; callers only branch on `Ok`/`Err`, not on the `Error`
  payload.

### Assessment
- **Coverage: partial.** Only `into_raw_value` has an `ensures`. The in-scope
  constructors/projections `from_frame_number`, `into_frame_number`, and
  `from_raw_value` have no contracts yet, even though callers depend on
  alignment, raw-value identity, and the frame-number round-trip described
  above.
- **Strength: weak on error paths.** No constructor states `Err` semantics or
  the `Ok ==> r.inv() && r@ == ...` post-conditions callers rely on (compare
  the sibling `phys.rs:126` which already has
  `result matches Ok(r) ==> r@ == addr@ && r.inv()`).
- **View design: caller-abstract (good).** `type V = int` models the physical
  address, which matches what `mm::phys::frame` specs reason about (`frame@`),
  not the internal `PageAligned<PhysicalAddress>`. The `into_raw_value`
  contract is written against this View and is reusable by all callers.
- **TCB constraint:** only `into_raw_value` is currently `external_body`-listed
  in `tcb-allowed.md`. Do **not** add `external_body` to the other in-scope
  functions; they should be given real `#[verus_spec]` contracts and verified
  against the `int` View.
