A Vmem represents an owned virtual address space: a partial mapping from page-aligned virtual addresses to backing physical frames, with per-page access permissions and copy-on-write state. The kernel half is shared while the user half is privately owned, and this whole structure gets loaded into the MMU via the page directory physical address.

Looking at what callers actually observe, I need to model user mappings (querying presence, decoding PTEs, iterating, translating addresses, mapping/unmapping, handling copy-on-write), kernel mappings (with less detail but still tracking presence and permissions), the page directory physical address as a stable field, and the active/loaded state.

The active state is tricky—it's really global MMU state rather than per-Vmem state, so I'll treat it as an external concern and keep the load operation's spec minimal. For the core View, I'm settling on three fields: a map from page-aligned user virtual addresses to user page entries, a similar map for kernel pages, and the page directory physical address. These capture the observable state that any implementation must maintain, and the user map already encodes ownership through which frames are mapped to which addresses.

For the user page entry itself, I need to track the backing frame's physical address, access permissions, and the copy-on-write flag. The tricky part is how to represent access permissions—callers care most about the writable bit and cow flag, but uctrl can set arbitrary permissions. I'm leaning toward storing an abstract AccessPermission type that captures the full permission state, since that's what the spec needs to express uctrl's postconditions. I'm settling on a concrete design: store `frame`, `perms` as an abstract AccessPermission value, and `cow` as a boolean. The `writable` property derives from perms through AccessPermission's spec interface, which captures the CoW invariant cleanly. For the design document, I'll present this principled approach with rationale rather than getting bogged down in whether to expose every permission bit.

For kernel pages, I'm debating whether to include the frame field. The minimal model for in-scope specs would be just `Map<int, AccessPermission>` since callers only observe perms via kctrl and presence via NoSuchEntry errors.
