- Callers assume:

    `frame::is_covered(...)` before booking, rather than relying on this function

    the function itself performs no range check.
  - The `Err` arm currently never occurs (body is `Ok(Self(addr))`), but callers
    propagate with `?` and treat `Err` as a benign skip.
- Callers don't care about:
  - Any RAM-range / bounds semantics — they specifically want the unchecked path.

## Abstract Resource
`PhysicalAddress` is an **opaque integer identifier for a byte location in
guest-physical memory**. Its caller-facing model is a single `int` (the raw
address), with two derived views: the **frame** it belongs to
(`addr >> FRAME_SHIFT`) and its alignment. The module provides conversions
between the address value, frame numbers, and (for MMIO) an unchecked wrapping of
a virtual/guest-physical address. Higher layers (frame allocator, page tables,
kernel modules) use it purely as an aligned address / frame-index source.

## Key Invariants (caller perspective)
- **Frame/address consistency:** `into_frame_number(p)@ == p@ >> FRAME_SHIFT`,
  and `from_number(n)@ == n.into_raw_value() * FRAME_SIZE`.
- **Round trip:** `from_number(n).into_frame_number() == n`; for any aligned
  physical address `p`, `from_number(p.into_frame_number()) == p`.
- **Totality of `into_frame_number`:** never panics for a validly-constructed
  `PhysicalAddress` (the internal `unwrap` is justified by validity).
- **`from_number` produces a `FRAME_SIZE`-aligned base address** (so downstream
  `PageAligned::from_address` succeeds).
- **`from_mmio_address` is identity & unchecked:** `Ok(p)` with `p@ == addr@`,
  no RAM-range validation, distinguishing it from the range-checked constructors.
- **Value model is just `int`:** the inner `VirtualAddress` newtype is invisible
  to callers; changing the wrapper without changing `view()` must not break specs.

### Assessment
- Coverage: **partial** — only `into_frame_number` is referenced by an upstream
  assumed spec, and even that has no `ensures`. `from_number` and
  `from_mmio_address` have no upstream specs.
- Strength: **weak** — the upstream `assume_specification` is a signature
  placeholder; it constrains nothing about the returned frame number.
- View design: **caller-abstract and adequate** — `int` (raw address) cleanly
  supports all callers (frame indexing, alignment, MMIO identity) without
  exposing the `VirtualAddress` wrapper. Recommend keeping `view(): int` and
  expressing `into_frame_number`/`from_number` ensures relative to `FRAME_SHIFT`/
  `FRAME_SIZE`, and `from_mmio_address` as an identity (`result@ == addr@`).
