## Trait Obligations
- Trait `BssStorage` (unsafe) — `as_mut_ptr()` must return a **stable** pointer
  to a writable, correctly aligned backing region of at least `STORAGE_SIZE`
  bytes, exclusively managed by this allocator, with
  `NUM_UNITS * stride <= STORAGE_SIZE`. `alloc` relies on this to bound-check
  slots (`base + offset + N <= base + STORAGE_SIZE`) and to trust alignment.
  Production impl: `PageTableBss` (page-aligned, `NUM_UNITS = NUM_KERNEL_PAGE_TABLES`).
- Trait `fmt::Display` for `BumpAllocError` — **used by callers** indirectly:
  every `alloc_as` error site formats the error with `{}` in `error!(...)`
  (e.g. `identity_map.rs:520`, `boot_init.rs:131`). Display must produce a
  human-readable reason. (Out of the verification scope but a real caller
  dependency.)
- Trait `Default` for `FixedSizeBumpAllocator` — just calls `new()`; not used by
  any caller. Singleton responsibility stays with the caller.

## Caller Expectations

### `FixedSizeBumpAllocator::alloc_as`
- Callers assume (success): a `&'static mut MaybeUninit<T>` pointing at a slot
  that is (a) **unique / non-aliasing** w.r.t. every prior allocation,
  (b) sized exactly `size_of::<T>() == N`, (c) aligned to `align_of::<T>() <= A`
  (page-aligned in practice), and (d) backed by stable static storage valid for
  `'static`. Every caller immediately follows with `.assume_init_mut()` and
  relies on the slot being **zero-initialized** (BSS) so the resulting
  `[PteWord; PAGE_TABLE_LENGTH]` reads as "all PTEs absent". (The zero-init
  guarantee comes from BSS via the `BssStorage` backend, not from `alloc_as`
  itself — but the View must not contradict it.)
- Callers assume (failure): an `Err(BumpAllocError)` is returned (never a panic
  on exhaustion). All callers collapse the error into
  `Error::new(ErrorCode::OutOfMemory, ...)`, so they only need: "failure ⇒ no
  slot was handed out and no state visible to me changed in a harmful way."
- Callers don't care about: which specific `BumpAllocError` variant is returned
  (they discard the distinction after logging), the atomic bump index, stride
  math, or how the byte slot is reinterpreted into `MaybeUninit<T>`.
- Would break callers if: a returned reference aliased an earlier slot; the
  size/alignment match guarantees were weakened; or a slot outside the backing
  region were returned.

### `FixedSizeBumpAllocator::alloc`
- No external callers; sole consumer is `alloc_as`, which assumes: a successful
  return is a `&'static mut [u8; N]` that is N-sized, A-aligned, within storage
  bounds, and **distinct** from all previously returned slots. Unit tests pin
  this contract: `alloc_returns_distinct_slots` (pointers differ),
  `alloc_returns_exhausted_error` (over-capacity ⇒ `Err(Exhausted)`).
- Callers don't care about: the CAS retry loop, `Ordering`, or offset arithmetic.
- Would break callers if: two calls ever returned overlapping pointers, or a slot
  exceeded `STORAGE_SIZE`, or exhaustion panicked instead of returning `Err`.

### `align_up`
- Callers assume: `align_up(v, a)` returns `Some(m)` where `m` is the least
  multiple of `a` with `m >= v`, and `None` only when `a == 0` or the rounded
  product overflows. Used in a **const** context to compute
  `PAGE_TABLE_SLOT_STRIDE`; `None` deterministically triggers a compile-time
  `panic!("page table slot stride overflow")`. Internally `alloc` uses the same
  function for the runtime stride (`align_up(N, A)`).
- Callers don't care about: that it is implemented via `div_ceil` + `checked_mul`.
- Would break callers if: it returned a non-multiple of `a`, a value `< v`, or
  `Some` where overflow actually occurred (would silently miscompute stride).

### `as_mut_ptr` (`BssStorage::as_mut_ptr`)
- Caller is `alloc` (`S::as_mut_ptr() as usize` → `base`). `alloc` assumes the
  returned base pointer is stable across calls, addresses a region of at least
  `STORAGE_SIZE` writable bytes, and is aligned enough that page-stride slots
  land on `A`-aligned addresses. `alloc` additionally guards with checked
  arithmetic and an explicit `ptr.is_multiple_of(A)` re-check, so it tolerates a
  base that is only as aligned as the backend promises.
- Callers (of `alloc`) don't care: which static object the pointer comes from.
- Would break `alloc` if: the pointer were unstable between calls, the region
  were smaller than `STORAGE_SIZE`, or it produced overlapping regions for
  distinct backends.

## Abstract Resource
A fixed-capacity pool of equally-sized, statically-reserved memory slots (page-
table-sized units carved from a page-aligned BSS region) that are vended **at
most once each** via a monotonic, lock-free bump index. From the caller's view
it is a one-shot slot allocator yielding unique `&'static mut` page-table-backing
buffers until capacity is exhausted.

## Key Invariants (caller perspective)
- **Uniqueness / no aliasing:** every successful `alloc`/`alloc_as` returns a
  slot disjoint from all previously returned slots (no two live `&'static mut`
  alias).
- **In-bounds + well-formed:** returned slots lie fully inside the backing region
  and satisfy the requested size (`N`) and alignment (`A`).
- **Bounded capacity, graceful exhaustion:** at most `NUM_UNITS` slots are ever
  handed out; the `NUM_UNITS + 1`-th request returns `Err(Exhausted)` rather than
  a bogus/overlapping slot or a panic.
- **Type-match gating (`alloc_as`):** a typed slot is only produced when
  `size_of::<T>() == N` and `align_of::<T>() <= A`; otherwise `Err` and no slot.
- **Thread-safe handout:** concurrent allocations never observe the same index
  twice (atomic compare-and-swap), so uniqueness holds under concurrency.
- **Stability:** returned references are valid for `'static` because the backing
  store is static and exclusively owned by the single allocator instance.
