- Callers assume:
  - `Some(fn)` is returned **iff** `value <= FrameNumber::MAX`
    (= `MAX_ADDRESS / FRAME_SIZE - 1`); otherwise `None`.
  - The wrapped value is preserved exactly:
    `from_raw_value(v).unwrap().into_raw_value() == v` (round-trip identity,
    relied on by the unit tests and by `phys.rs`'s total `unwrap()`).
  - It is a pure, total, side-effect-free check — no panics, no global state.
  - Most callers turn `None` into a domain error (`OutOfMemory` /
    `InvalidArgument` / `BadAddress`) via `?` / `ok_or_else`, so they rely on
    `None` being the *only* failure signal (no panic / no silent truncation).
  - `phys.rs:211` relies on `Some` being guaranteed when the caller already
    knows `value <= MAX` (the `unwrap()` must never panic for an in-range index).
- Callers don't care about:
  - The internal representation (a `usize` newtype) — only the round-trip and
    the range boundary matter.
  - The exact numeric definition of `MAX`, only that it is the inclusive upper
    bound and matches `into_raw_value`'s range.

  - The result is bounded: `0 ..= FrameNumber::MAX`. This bound is load-bearing:
    - `pde/pte`: `raw << FRAME_SHIFT` must not overflow / lose bits.
    - `phys.rs::from_number`: `raw * FRAME_SIZE <= usize::MAX` no-overflow proof

      explicitly bound-check against `refcount.len()`, but rely on the index
      being the genuine frame number.
  - Pure, total, `self`-by-value (consumes a `Copy` value) — no panic, no
    mutation, deterministic.
- Callers don't care about:
  - How the value is stored internally; only that it equals the original raw
    index and stays within `[0, MAX]`.

## Abstract Resource
`FrameNumber` is the abstract identity of a physical page frame — a bounded
non-negative integer index in `0 ..= MAX` (where `MAX = MAX_ADDRESS/FRAME_SIZE
- 1`). It is a validated newtype over `usize` that callers use to move safely
between raw frame indices, physical addresses (`index * FRAME_SIZE`), and
page-table entry encodings (`index << FRAME_SHIFT`).

## Key Invariants (caller perspective)
- **Range invariant:** every `FrameNumber` value satisfies
  `0 <= into_raw_value() <= MAX`. No `FrameNumber` outside this range can exist.
- **Round-trip identity:**
  `from_raw_value(v) == Some(f)  ==>  f.into_raw_value() == v`, and
  `from_raw_value(v) == None  <==>  v > MAX`.
- **Totality / purity:** both operations are pure and total (no panics, no
  side effects); the only observable failure is `from_raw_value` returning
  `None` for out-of-range input.
- **No-overflow enablement:** the upper bound `MAX` is chosen so that
  `raw * FRAME_SIZE` and `raw << FRAME_SHIFT` never overflow `usize` — callers
  in `phys.rs`, `pde.rs`, `pte.rs` depend on this.
- **Sentinel:** `NULL` denotes frame `0` and is always valid.

### Assessment
- Coverage: partial — the boundary contracts cover exactly what `phys.rs`
  needed (range + `Some`/`None` condition + index preservation), which happens
  to align with what all other callers need too.
- Strength: adequate for `into_raw_value` (range + identity) and
  `from_raw_value` (iff-condition + preservation). No error-path detail is
  required beyond `None`, since `from_raw_value` cannot fail any other way.
- View design: a `View` mapping `FrameNumber -> int` (the raw index, with
  invariant `0 <= v <= spec_max_frame_number()`) would be caller-abstract and
  satisfies every caller. The existing boundary specs are stated against the raw
  `usize`/`spec_max_frame_number()` projection, not biased toward `phys.rs`
  internals, so they are a strong starting point for the real in-module spec.
