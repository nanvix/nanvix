## Spec Quality

The external-top API contracts are correct, complete for their callers, and
declarative.

**View / `inv`.** `type V = int`, `closed spec fn view(&self) -> int { self.0 as
int }`. The scalar `int` View is the idiomatic single-value abstraction (matches
`PhysicalAddress`/`FrameAddress`). `closed` correctly hides the `usize`-newtype
mapping; callers still recover a concrete `usize` via the `into_raw_value`
contract bridge (`result as int == self@`). `inv()` is `pub open` and encodes the
single load-bearing well-formedness fact `0 <= self@ <= spec_max_frame_number()`,
declared `#[verifier::type_invariant]` so it holds for **every** value without a
precondition — precisely what `into_raw_value`'s unconditional range guarantee
needs.

**`into_raw_value`** — `ensures result as int == self@` (newtype-identity
projection) and `0 <= result as int <= spec_max_frame_number()`. The body
`proof!{ use_type_invariant(&self); } self.0` correctly imports the type
invariant to discharge the range. The range clause is *derivable* from
`result as int == self@` plus `self.inv()` (open), so it is technically
redundant; however it is the documented caller-facing trust boundary recorded in
`tcb-allowed.md` ("projects index in `0 ..= spec_max_frame_number()`") and saves
every no-overflow caller from re-invoking `inv()`. This is intentional,
caller-oriented redundancy — **not** a harmful subsumed ensures.

**`from_raw_value`** — `ensures (result is Some) <==> (value as int <=
spec_max_frame_number())` and `result matches Some(f) ==> f@ == value as int &&
f.inv()`. The `iff` gives the error path a precise bidirectional meaning
(`None <==> value > max`) — no tautological `=> true`. Index preservation
(`f@ == value as int`) plus the contracts algebraically yield the round-trip
identity `from_raw_value(v).unwrap().into_raw_value() == v`. `f.inv()` is again a
convenience restatement (derivable) matching the upstream contract; benign.

**Soundness of the boundary math.** `spec_max_frame_number() = MAX_ADDRESS as int
/ spec_frame_size() - 1` with `spec_frame_size() = FRAME_SIZE as int`, which
mirrors the exec `FrameNumber::MAX = mem::MAX_ADDRESS / mem::FRAME_SIZE - 1`
(usize floor division equals `int` floor division for non-negative operands).
So `MAX as int == spec_max_frame_number()`, making the in-module contract and the
callers' assumed `tcb-allowed` contract definitionally identical. Verification
CLEAN confirms `NULL = Self(0)` and both constructors satisfy the type invariant.

Verdict: **high quality**, no tautological/harmful-subsumed/meaningless-error
clauses.
