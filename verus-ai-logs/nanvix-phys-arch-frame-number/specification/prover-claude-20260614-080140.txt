## Summary

Added Verus specs to `FrameNumber` (`arch` crate) and superseded the now-redundant kernel placeholders.

**Design (key decisions):**
- **View**: `FrameNumber` → `int` (closed `view = self.0 as int`), modeling the raw frame index.
- **Bound**: an *associated* `pub uninterp spec fn FrameNumber::spec_max() -> nat`, tied to the exec const `MAX` via `assume_specification[FrameNumber::MAX]`. Keeping it uninterp (rather than interpreting `MAX = MAX_ADDRESS/FRAME_SIZE-1`) avoids annotating `PAGE_SIZE`/`FRAME_SIZE`, which would conflict with—and risk—the kernel's `spec_page_size`/`FRAME_SHIFT` model. Using an *associated* fn (vs. a free fn) let the kernel reach it through the already-`pub` type, avoiding cfg-gated re-exports that tripped the cheating heuristic.
- **Type invariant** (`0 <= self@ <= spec_max()`): gives the unconditional `0..=MAX` bound the kernel's `into_raw_value` contract requires (no `requires`), underwriting overflow-safe `<< FRAME_SHIFT`.
- `MAX` lives in a plain (non-verified) impl so it's external — no spurious warnings.

**Supersession (kernel):** removed the placeholder `ExFrameNumber` external-type-spec and the `from_raw_value`/`into_raw_value` `assume_specification`s; re-expressed the kernel's two uninterp helpers as `open` definitions over the arch quantities (`spec_frame_raw_value(f) := f@`, `spec_max_frame_number() := FrameNumber::spec_max() as int`), so every existing kernel proof site verifies unchanged.
