[THINKING] I've got enough context now to move forward. `UserFrame` is an owning RAII wrapper around a physical user frame address, where dropping it automatically frees the frame by decrementing its refcount. The constructor simply takes an address and wraps it into a handle.

Callers use it in two ways: as an owning handle that gets freed on drop (like in copy-on-write scenarios), or wrapped in `ManuallyDrop` to prevent automatic cleanup when transferring ownership elsewhere. The `address()` method returns the physical address for page table mapping without consuming the handle, while `leak()` transfers ownership to the page table and suppresses the drop. The `share()` method increments the refcount and returns a new aliased handle—callers depend on this succeeding atomically or failing without side effects. The `refcount()` method lets callers check if they have exclusive access for optimization. The pool facade `Upool` manages allocation from the global frame allocator, with `alloc()` returning a new `UserFrame` handle.

The core abstraction is a refcounted handle to user-space physical frames, where the reference counting ensures safe sharing and automatic reclamation.
