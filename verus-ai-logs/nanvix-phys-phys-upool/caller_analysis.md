## Module Overview

`upool.rs` provides two types:

- **`UserFrame`** — an *owning handle* to a single reference-counted physical
  user frame. It stores only a `FrameAddress`. All real work is delegated to the
  module-level `frame` allocator:
  - `share`  → `frame::share`  (increment refcount)
  - `refcount` → `frame::refcount` (query refcount)
  - `drop`   → `frame::free`    (decrement / release on scope exit)
- **`Upool`** — a zero-sized facade (`_private: ()`) that is the dedicated entry
  point for user-frame allocation (`alloc` → `frame::alloc`).

All callers live under `src/kernel/src/mm/` (`virt/vmem.rs`, `virt/manager.rs`,
`phys/manager.rs`, `phys/mod.rs`, `elf.rs`).

## Trait Obligations

- **Trait: `Drop for UserFrame`** — expected semantics: when a live `UserFrame`
  goes out of scope, it **releases exactly one reference** to its physical frame
  (`frame::free`), freeing the frame only when the last reference drops. Errors
  are logged, not propagated. Callers rely on this for automatic refcount
  release and for CoW reference dropping (`drop(UserFrame::new(old_frame))` at
  `vmem.rs:895`) and error-path rollback (a failed `map` drops the unmapped
  handle, releasing the freshly `share`d reference).
- **Trait: `View for UserFrame`** (already present in the file) — `view() : int`
  is the physical address of the owned frame (`self.addr@`). Upstream specs
  already depend on this: `PhysMemoryManager::alloc_user_frame` ensures
  `phys_view().frames.allocated_frames.contains(frame@)` and
  `frame@ % spec_page_size() == 0` over the returned `UserFrame`.

## Abstract Resource

`UserFrame` is an **RAII owning handle to one reference of a reference-counted
physical user frame**, identified abstractly by its physical address
(`view() : int`). `Upool` is the stateless allocation entry point that mints such
handles. The module manages *ownership of frame references*, not frame storage —
the actual refcount/bitmap state lives in the `frame` allocator.

## Key Invariants (caller perspective)

- A `UserFrame`'s `view()` is the physical address of the frame it owns and is
  **stable**: `address()@ == self@`, and `new(a)@ == a@`.
- A live `UserFrame` owns exactly **one** reference to its frame.
  - `Drop` releases exactly one reference (frees on the last).
  - `leak` discards the handle **without** releasing its reference (frame stays
    allocated).
  - `share` **adds** one reference and yields an aliasing handle with equal view.
  - `refcount`/`address` are pure: they neither consume the handle nor change the
    refcount.
- `Upool::alloc` (and thus `alloc_user_frame`) yields a handle to a newly
  allocated, **page-aligned** frame on success; on error no frame is allocated.
- Construction (`Upool::new`, `UserFrame::new`) performs no allocation and no
  refcount change.
