## Trait Obligations
- Trait: `View for KernelFrame` (defined inline in `kframe.rs`) — `type V = int`;
  `view(&self) == self.base@`. The abstract value of a kernel frame **is** the base
  physical address of the frame it owns. Allocator contracts in
  `phys/manager.rs` name returned frames purely through this `@` (e.g.
  `phys_view().frames.allocated_frames.contains(frame@)`, the contiguity predicate
  `kernel_frames_contiguous(frames@, base)`). No caller inspects storage layout.
- Trait: `Drop for KernelFrame` — on scope exit the frame's base is returned to the
  global frame allocator via `super::frame::free(self.base)`. `Drop` must be
  `no_unwind` / `opens_invariants none` (errors are logged, never panic), matching
  the `free` shim contract in `frame.rs` (lines 762–779). Callers rely on this for
  RAII cleanup and rollback (see `alloc_many_kernel_frames`, `alloc_kpages`).
- Trait: `Deref` / `DerefMut for KernelFrame` — yield a `PAGE_SIZE` `[u8]` slice at
  the identity-mapped base. Out of scope (TCB), but callers like the kstack guard
  watermark code read/write through this slice; the CR3 safety invariant is the
  caller's obligation (documented in the impls' `# Safety`).

- `phys/manager.rs:430` — `PhysMemoryManager::alloc_many_kernel_frames`: wraps each

(The script's line numbers 253/302 for `new` point at `#[verus_spec]`
`requires`/`ensures` text on neighbouring trusted shims, not real call sites —
disregarded; the genuine constructors are 354 and 430.)

- Callers assume on `Ok(frame)`:
  - `frame@` equals the `base` that was passed in (the `@`/`base()` of the result is
    the input address) — needed so `manager` can assert
    `allocated_frames.contains(frame@)` and the ascending page-stride contiguity
    predicate over the returned run.
  - The frame is now identity-mapped in the kernel address space (so later
    `Deref`/`DerefMut`/`clear` are sound). This is `new`'s real side effect
    (`virt::identity_map_page`), but no caller depends on it abstractly — they only
    need the address-equality and the fact that the frame is now a valid owned
    resource that will free itself on drop.
- Callers assume on `Err`:
  - **No frame ownership was transferred** — the input `base` is still the caller's
    responsibility to free. Both call sites rely on this: they explicitly
    `frame::free` the raw address themselves on the error path. So `new` must NOT
    free `base` on failure (and indeed it does not — it returns before constructing
    `Self`).
- Would break callers if changed: the result's `base()`/`@` no longer equalling the
  input `base`; freeing/consuming `base` on the error path; constructing a frame that
  is not identity-mapped (would make later `clear`/deref fault).
- Callers don't care about: page-alignment check vs identity-map ordering, the
  `PageAligned`/`PhysicalAddress` conversion path, error-code specifics, or that the
  PTE comes from a BSS page-table pool.

### `KernelFrame::drop(&mut self)`  [trait `Drop`, implicit]
Dispatched implicitly whenever a `KernelFrame` goes out of scope, is overwritten, or
a `Vec<KernelFrame>` is cleared/dropped. Relied on as the RAII rollback mechanism:
- `phys/manager.rs:434` (`frames.clear()` in `alloc_many_kernel_frames`),
- `virt/manager.rs:753` (`kframes.clear()` in `alloc_kpages` on clear failure),
- normal end-of-scope drops of `KernelPage`/`KernelStack`/`Vmem` page-dir frames.

- Callers assume: dropping a `KernelFrame` releases its frame back to the global
  allocator (`free(self.base)`), preserving the phys subsystem invariant
  (`phys_view().inv()`), and **never panics / never unwinds** (errors are logged).
  This is what makes `Vec::clear()` a sound bulk-free and lets allocator functions
  hand out RAII-owned frames.
- Callers don't care about: the log message, or the exact refcount transition (the
  `free` shim already documents this is not expressible against a single fixed
  `phys_view()`).

### `KernelFrame::clear(&mut self) -> Result<(), Error>`  [`pub`, out-of-scope / TCB]

## Abstract Resource
`KernelFrame` is an **owned RAII handle to a single page-sized physical frame**
allocated for kernel use and identity-mapped into the kernel address space. Its
abstract value is exactly the frame's **base physical address** (`@ == base@`). The
backing physical-frame pool is the `FrameAllocView` resource managed by the rest of
`mm::phys`; a live `KernelFrame` corresponds to one address in that view's
`allocated_frames`, and dropping it returns that address to `free_frames`.

## Key Invariants (caller perspective)
- **Address identity:** `result@ == base@` after `new(base)`, and `base()@ == self@`
  always; the address is page-aligned and immutable for the handle's lifetime.
- **Ownership transfer is all-or-nothing:** `new` takes ownership of `base` only on
  `Ok`; on `Err` the caller still owns/must-free `base`.
- **RAII conservation:** every successfully constructed `KernelFrame` frees its frame
  exactly once on drop, preserving `phys_view().inv()`; drop never unwinds.
- **Identity-mapped backing:** a live `KernelFrame` is safe to `clear`/deref within
  the kernel CR3 (established by `new`'s `identity_map_page`).
