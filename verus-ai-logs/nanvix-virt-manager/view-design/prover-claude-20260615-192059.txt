## Key design decision

`VirtMemoryManager` is a **zero-sized, stateless singleton façade**, so its own View is a **unit marker** (`VirtMemoryManagerView;`, `inv() == true`). A field-bearing manager View fails the substitution test by construction — it could only mirror the global `PhysMemoryManager` or a `Vmem` registry the manager doesn't own or expose through `&mut self`. The caller analysis confirms this ("the View must model the address space, not the empty manager").

The real abstraction boundary is the **inherited `VmemView`** (already implemented in `vmem.spec.rs`). I re-evaluated all six `VmemView` fields against all nine manager entry points (substitution-test table) → **keep all, rename none, add none**.

What the manager phase *contributes* is **vocabulary**, not state — free `pub open spec fn`s over `VmemView`:
- `spec_is_cow_write_fault(ec)` — pure error-code decode (present∧write∧user)
- `region_user_unmapped` / `maps_user_run_with` — `alloc_upages` range shape
- `links_child_cow` / `logically_writable` / `link_user_pages_pre` — fork CoW relation

Single-page ops (`try_unmap_upage`, `ctrl_upage`, `try_resolve_cow_fault`) reuse inherited transitions (`spec_unmap`, `spec_uctrl`, `spec_resolve_cow`) directly.

The global frame pool (`alloc_kpage`/`alloc_kpages`) is deliberately left **external** — specified via returned RAII values' validity — paralleling `VmemView`'s rejection of global CR3/physical memory.
