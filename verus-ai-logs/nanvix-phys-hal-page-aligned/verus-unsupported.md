# Verus-Unsupported Constructs — `kernel::hal::mem::types::address::aligned::page`

This file records a Verus tool limitation hit while verifying the `page` module.
It is an **internal Verus assertion panic**, not a Nanvix code bug and not a
proof gap. No exec code was changed and no `external_body` was added to work
around it (the function is not in `tcb-allowed.md`).

## 1. Verifying a generic trait impl panics Verus (`inherit_default_bodies`)

### Where
`src/kernel/src/hal/mem/types/address/aligned/page.rs`

```rust
impl<T: Address> Address for PageAligned<T> {
    fn into_raw_value(self) -> usize { self.0.into_raw_value() }
    // ... clone_address, from_raw_value, align_up, align_down,
    //     is_aligned, max_addr, as_ptr, as_mut_ptr
}
```

To machine-verify the body of `PageAligned::into_raw_value` against its trait
contract (`result as int == self@`) the **whole** trait impl must be annotated
(`#[verus_verify]` on the `impl` block). Verus does not allow annotating a single
method of a trait impl:

```
error: In order to verify any items of this trait impl, the entire impl must be
verified. Try wrapping the entire impl in the `verus!` macro.
```

### Exact error (when the `impl` block is annotated `#[verus_verify]`)
```
thread 'rustc' panicked at vir/src/traits.rs:511:13:
assertion failed: !method_impls.contains(&p)
...
vir::traits::inherit_default_bodies
error: could not compile `kernel` (bin "kernel")
```

The duplicated `(impl_path, method)` key is `into_raw_value` — the only `Address`
method that takes `self` **by value** and whose trait declaration carries a
`#[verus_spec]` referencing `self@` (`src/libs/sys/src/sys/mm/address/mod.rs`).

### Minimal trigger / isolation
- Trigger is the **generic** trait impl: annotating the non-generic
  `impl Address for PhysicalAddress` does *not* panic (it proceeds past this
  point). The generic `impl<T: Address> Address for PageAligned<T>` (and the
  structurally identical `impl<T: Address> Address for PageTableAligned<T>` in
  `pgtab.rs`) does panic.
- Removing the trait-declaration `#[verus_spec]` on `into_raw_value` does **not**
  avoid the panic — the duplicate `TraitMethodImpl` registration for the generic
  impl still occurs during HIR→VIR lowering.
- Verus version: `0.2026.05.24.ecee80a` (pinned in `build/verus-version`; the
  newest binary available on this machine). Older local binaries
  (`0.2026.05.13`) are not newer and were not tried as a downgrade.

### Why it is unsupported
The assertion is inside `inherit_default_bodies`, which builds the set of
`(impl_path, trait_method)` pairs from `krate.functions`. For this generic trait
impl Verus registers two `FunctionKind::TraitMethodImpl` entries with the same
key for `into_raw_value`, violating the `assert!(!method_impls.contains(&p))`
invariant. This is an internal verifier bug — there is exactly one user-written
`impl Address for PageAligned` in the crate (confirmed by grep), so the duplicate
is generated by Verus, not by the source.

### Mitigation (no trust boundary introduced)
The `impl` block is left **unannotated**, exactly as it ships. Consequences:
- `PageAligned::into_raw_value`'s **contract still reaches callers**: the trait
  declaration `Address::into_raw_value` carries `ensures result as int == self@`,
  and that postcondition is in force at every call site (the contract is a
  property of the trait method, inherited by all impls).
- Only the one-line projection body `self.0.into_raw_value()` is not
  independently machine-checked. It is trivially correct: `self@ == self.0@` (by
  the `View` impl) and the inner `T::into_raw_value` ensures
  `result as int == self.0@`, so `result as int == self@`.
- This is **not** `admit()` / `assume()` / `external_body` — it is the default
  state of any unannotated trait impl (the same status as the module's other
  out-of-scope `Address` methods and the sibling `pgtab` module).

### Deferred work
When an upgraded Verus fixes the `inherit_default_bodies` duplicate-registration
assertion, re-add `#[verus_verify]` to `impl<T: Address> Address for
PageAligned<T>` and confirm `result as int == self@` proves from `self@ ==
self.0@` plus the inner `T::into_raw_value` trait spec (no proof body needed).
